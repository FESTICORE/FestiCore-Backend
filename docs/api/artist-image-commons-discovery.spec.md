# 누락 출연진 Commons 사진 후보 자동 탐색 (#139)

## 목표

매일 00:00 KST 이후 이미지가 없는 공개 출연진을 대상으로 Wikimedia Commons의 파일 후보와 원본 메타데이터를 탐색해 관리자 전용 실행 증거에 기록한다. 검색 결과를 공개 사진으로 자동 연결하지 않는다.

## 계약

- 탐색 대상은 공개 축제·발행 시간표에 포함된 출연진 중 현재 저장 이미지가 없는 원래 이름이다. 축제 ID와 원본 URL을 신원 키로 유지한다.
- 전용 `artist-image-discovery` 소스 한 개가 기존 일일 스케줄러와 실행 잠금을 사용한다. 일반 소스 등록 API로 이 종류를 생성하거나 다른 종류로 전환할 수 없다.
- Commons 검색은 고정된 `https://api.wikimedia.org/core/v1/commons/` 공식 API 게이트웨이로만 요청한다. Commons 사이트의 `robots.txt`가 금지하는 `/w/api.php` 경로는 사용하지 않는다. 요청당 검색 수와 후보 수, 실행당 출연진 수, 응답 크기와 시간을 제한한다.
- 각 대상마다 `candidates`, `no-results`, `failed`를 구분한다. 후보는 항상 `pending`이며 원본 URL, 파일 식별자, MIME을 관리자에게 보여 준다. 저작자·라이선스는 API에서 확인되지 않으면 `null`과 `unverified`로 기록한다. HTML 메타데이터를 그대로 렌더링하지 않는다.
- 관리자 viewer 이상만 실행 증거를 조회한다. 기존 공개 축제 API, `crawl_images`, 타임테이블, 소향의 일일 권리 검증 정책은 바꾸지 않는다.
- `GET /api/v1/admin/crawl/runs/{runId}/artist-image-discovery`는 해당 실행의 비공개 후보 증거를 `code`, `data`, `message` 응답으로 반환한다. 일반 실행 목록에는 후보 본문을 포함하지 않는다.
- 후보 0건도 정상 탐색 결과로 저장한다. 네트워크/API 오류는 실패로 기록한다.

Commons 검색은 API 게이트웨이의 `/search/page`를, 파일 정보는 공식 [Get file API](https://api.m.wikimedia.org/wiki/Core_REST_API/Reference/Media_files/Get_file)를 사용한다. 파일 정보에는 저작자와 라이선스가 없을 수 있으므로 근거가 확인되지 않으면 `null`로 둔다. 검색 결과의 HTML 발췌를 그대로 렌더링하지 않는다. 파일 페이지와 라이선스 메타데이터가 검색 결과에 있다는 사실만으로 공연 출연진의 신원이나 사진 공개 권한을 승인하지 않는다. API 게이트웨이의 단계적 사용 중단 가능성은 실패 결과로 드러내고 추후 공식 대체 경로를 확인한다.

## 검증

- 순수 파서 단위 테스트: 정확한 파일만 후보화, 동명이인 자동 승인 금지, 누락·위험 메타데이터 배제, 후보·응답 크기 제한, API 오류 구분.
- 서비스 테스트: 누락 대상만 조회, 일별 중복 방지, 비공개 실행 증거, 일반 등록 API의 전용 종류 거부.
- 타입 검사·린트·Nest 빌드·관련 Jest·PostgreSQL migration·CI를 통과한다.
- 개발 서버 수동 실행으로 증거 저장·조회와 공개 이미지 미변경을 확인한다.

## 한계

Commons 검색 결과의 이름과 CC 표기는 실제 공연 출연진의 신원과 재사용 허락을 확정하지 않는다. 공개 반영은 원본 파일별 신원·권리 검토와 지속 검증을 구현한 별도 변경에서만 진행한다. 현재 사진 누락 28명과 시간표 이미지 2건은 이 PR만으로 해소되지 않는다.
