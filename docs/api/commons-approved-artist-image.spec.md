# Commons 출연진 사진 검토·공개 (#139)

## 목표와 완료 조건

Commons 검색 후보는 비공개로 유지한다. 운영자가 공식 공연의 출연진과 Commons 파일의 인물·권리를 확인한 사진만 서버에 저장해 공개한다. 목록·상세·시간표·발행 팩·이미지 URL에 동일한 공개 조건을 적용한다. 권리 확인이 실패하거나 36시간이 지나면 조건부 요청의 304를 포함해 더는 사진을 제공하지 않는다.

## 승인과 수집

- owner 전용 검토 API는 최근 discovery run의 후보 ID, 축제 ID와 원본 URL, 정확한 출연진 이름, Commons File 페이지 URL, 공식 출연 증거 URL을 받는다. 공식 출연 증거는 축제 원본 페이지 자체 또는 축제 원본과 같은 호스트에 있으며 해당 축제에 연결된 활성 `discovery`·`timetable`·`notice`·`artist-gallery` 소스여야 한다. Commons/Wikipedia 및 `artist-image` 소스는 공식 출연 증거로 사용할 수 없다. 해당 run의 target에 기록된 `festivalSourceUrl`·`artistName`·Commons file key가 요청과 정확히 일치하지 않으면 422다. 승인자는 Commons 설명의 인물과 공식 출연 증거의 인물을 직접 비교한다. 제목/검색 결과/동명이인 추측만으로 승인하지 않는다.
- 별도 `crawl_artist_image_reviews` 테이블에 검토 상태, 검토자·시각, 축제/출연진/Commons file ID, 공식 증거 URL, 확인한 저작자·라이선스, 허용된 원본의 콘텐츠 SHA-256, 연결된 source/run/image ID를 기록한다. 승인과 취소는 감사 로그에 남긴다. 출연진 이름·별칭·축제·파일·권리 중 하나라도 바뀌면 기존 승인을 편집하지 않고 새 검토를 요구한다.
- 현재 축제 카탈로그의 해당 `festivalSourceUrl`에서 정확한 출연진 이름이 단일하게 확인되지 않으면 승인 요청은 422로 거부한다. 공연 원본이 이미지나 합쳐진 자료뿐이라 자동 판별이 불가능한 경우도 422로 거부하며 이 버전에서는 공개하지 않는다. 매 수집마다 소속·이름을 다시 확인하고 불일치 시 공개를 중단한다. 공식 증거 URL은 HTTPS 호스트 제한, robots 정책, 리다이렉트 제한을 거쳐 확인한다.
- 검토 준비 시 비활성 `commons-approved-profile` artist-image 소스와 비공개 수집 run을 만들고 원본을 가져온다. 다운로드한 **변환 전 바이트**의 SHA-256을 새 image/review 컬럼에 저장하며 기존 WebP `contentHash`와 구별한다. 관리자는 서버가 저장한 바로 그 이미지를 보고 검토한다. 승인 트랜잭션에서 준비된 image ID·원본 SHA-256·현재 출연/권리 근거를 고정하고 소스를 활성화한다. 준비 이미지가 바뀌었으면 승인하지 않는다.
- Commons 파일 설명에서 실제 이미지 원본 URL, 저작자, 이미지 라이선스와 차단 템플릿을 읽는다. Commons 페이지 텍스트의 일반 라이선스는 이미지 라이선스로 취급하지 않는다. `creativecommons.org/licenses/by/{2.0,2.5,3.0,4.0}`만 정확히 허용한다. 복수 라이선스, NC/ND/SA, 삭제 요청, 검토 실패, 인격권·초상권 우려 표기가 있거나 저작자/라이선스를 구조적으로 확인할 수 없으면 승인하지 않는다. 저작자 표시는 마크업 제거 후 저장한다.
- 승인된 소스는 매일 원본·권리·출연진을 다시 확인하고 run 증거에 승인 image ID와 변환 전 원본 SHA-256을 기록한다. 이미지 행이 재사용되어도 매 run의 권리 증거는 별도로 남긴다. 동일 Commons URL에 다른 바이트가 업로드되면 기존 승인 이미지가 자동 교체되지 않는다. 원본 SHA-256 불일치 또는 확정 권리 변경은 승인 철회·소스 비활성화·감사 기록을 남기고 공개를 중단한다. 재공개에는 새 검토가 필요하다. 네트워크 실패는 사진을 숨기되 승인 철회로 취급하지 않는다. 저장은 기존 HTTPS·SSRF·MIME·크기·디코딩 검사와 WebP 변환을 사용한다.
- `parserConfig`는 전용 허용 키와 문자열 값만 받는다. `artistAlias` 및 임의 URL·이미지 힌트는 거부한다. 기존 generic artist-image 공개 SQL에서 새 seed를 명시적으로 제외한다.
- `commons-approved-profile`은 서버 관리 seed이므로 일반 소스 POST·PATCH에서 거부한다. 최신 완료 run의 성공 값은 `unchanged` 또는 `nochange-parsed`와 별도의 `artistImageRightsEvidence.status = ok`가 동시에 있는 경우로 한정한다.

권리 실패는 다음처럼 처리한다.

| 신호                                                                                                           | 처리                                                                                                                 |
| -------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| 원본 SHA-256·저작자·라이선스 불일치, 차단 템플릿, Commons 파일 또는 원본 이미지 404/410, 연결된 공식 근거 해제 | 승인 철회·소스 비활성화·감사 기록. 파일 제목이 일치하지만 권리 메타데이터를 파싱할 수 없는 경우도 안전하게 철회한다. |
| 타임아웃·429·5xx·robots 조회 실패, 파일 제목을 확인할 수 없는 구조 변경                                        | 해당 run 실패로 사진을 숨기되 기존 검토 상태는 유지한다.                                                             |

## 공개와 무효화

- 새 seed의 공개 SQL은 승인 상태, source enabled, 현재 출연진 연결, 승인된 image ID·원본 해시를 모두 요구한다. 해당 소스의 **가장 최근 완료된 run**(`startedAt DESC, id DESC`)이 성공했고 그 run이 승인 image에 연결되었으며 완료 후 36시간 이내여야 한다. 최신 run 실패 시 즉시 숨긴다. 직접 이미지 GET도 같은 SQL을 사용하며 `Cache-Control: no-store`를 보낸다. 소스 비활성화·승인 취소·권리 만료 시 404다.
- 검증된 `author`, `license`, `licenseUrl`, `sourceUrl`, `changes`는 review/image ID에 묶어 저장한다. 공개 조회의 이미지 ID와 동일한 행에서 출처를 읽는다. 소향 상수는 소향 이미지에만 적용한다. 다른 출처를 가진 두 아티스트의 목록·상세·시간표 출처는 서로 섞이지 않는다.
- 발행된 축제의 팩·상세·목록·버전 응답도 현재 공개 이미지 조건을 읽는다. Redis에서 원본 팩을 읽은 **뒤** 공통 `overlayPublishedImages(pack)`가 현재 사진·출처를 덧씌우고 `{document, etag}`를 반환한다. ETag는 packVersion뿐 아니라 현재 붙는 image ID, 권리 run ID, 만료 상태를 반영한다. 버전 응답과 팩의 ETag는 항상 같다. 조건이 변하면 이전 `If-None-Match`에 304 대신 사진 없는 200을 반환한다. 캐시가 권리 판정보다 오래 유지되지 않게 한다.
- 발행 팩에 저장된 `/api/v1/festivals/images/{id}.webp`도 동일한 공개 SQL을 통과해야 하며, 승인 사진의 출처는 해당 검토본에서 읽는다. 검증에 실패한 저장 이미지 URL은 제거한다. 현재 권리 검증을 통과한 승인 사진만 빈 아티스트 이미지에 덧씌운다.

## 검증

- 승인: 정확한 인물과 출연 근거, 중복 이름, 변경된 축제 소속, 임의 별칭/설정, 권리·차단 템플릿, 동일 URL 다른 원본 바이트, SSRF/리다이렉트/이미지 위장.
- 공개: 승인 image ID와 다른 ID, 가장 최근 실행 실패, 36시간 만료, source 비활성화, 승인 취소, 직접 GET의 `no-store`와 404.
- 목록·상세·시간표·발행 팩의 실제 출처와 이미지 연결, Redis 캐시 상태, 만료 뒤 `If-None-Match`가 200으로 바뀌는지 검증한다.
- 변경 범위의 Jest, 빌드·린트·형식 검사, CI를 통과하고 개발 배포 API의 실제 응답을 확인한다.

## 한계

Commons 사진 파일의 권리는 명세만으로 확정할 수 없다. 서버가 검사하는 필드와 별도로 운영자의 인물·공식 출연 증거 검토가 필요하다. 검증 불가능한 후보는 비공개로 남긴다.
