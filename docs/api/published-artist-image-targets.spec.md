# 공개 출연진 사진 누락 대상 일치 (#139)

## 목표와 검증 기준

- 일일 Commons 탐색의 `missingArtistImages()`가 발행 축제의 사진 유무를 실제 공개 상세 API와 같은 기준으로 판단한다. 승인·권리 확인을 통과해 공개되는 사진은 탐색 대상에서 제외하고, 철회·만료·최신 실패로 공개되지 않는 저장 사진은 탐색 대상에 포함한다.
- 발견 축제의 기존 검증된 시간표·라인업 수집 경로와 비공개 후보/승인 경계는 유지한다. 공연명이나 아티스트별 URL을 코드에 고정하지 않는다.
- 여러 발행 축제를 한 번의 이미지 SQL 조회로 검사하고, 축제별 저장 이미지 ID와 승인 축제 ID로 결과를 분리한다. 다른 축제의 동일 이름·사진·권리 실행이 현재 축제의 이미지나 ETag에 섞이면 안 된다.

## 구현

1. `publishedWithEtag()`의 공개 이미지 SQL을 배치 입력 `{festivalIds, storedIds}` 함수로 추출한다. 기존 `PUBLIC_CRAWL_IMAGE_SQL`, 컬럼, 최신 완료 run 조건은 그대로 사용한다. 빈 입력은 조회하지 않는다.
2. 발행 팩별로 저장 이미지 ID 또는 해당 축제에 승인된 행만 선택하고, Commons 행에는 현재 축제 ID·공식 원본 URL·정규화된 이름의 단일 출연 일치를 검사한다. 기존 `overlayPublishedImages()`를 재사용한다. 단건 공개 경로는 Redis 팩과 현재 DB 출연진 비교를 계속 적용한다.
3. `missingArtistImages()`는 이미 읽은 발행 팩 전체에 동일한 공개 이미지 정책을 한 번에 적용한 뒤 누락 출연진을 계산한다. 발견 축제의 기존 이미지 연결은 유지한다.

## 확인

- 단위 테스트: 승인 Commons 사진이 빈 팩에 적용되면 탐색 대상 제외; 저장 URL의 승인 철회/만료는 탐색 대상 포함; 유효한 기존 사진 유지; 다른 축제 같은 이름 격리; 공식 원본 URL·현재 출연진 불일치 시 제외; 다수 발행 축제에서도 이미지 SQL 한 번.
- 단건 공개 팩·ETag 회귀와 일일 discovery 테스트; `npm test -- --runInBand`, `npm run test:e2e -- --runInBand`, 전체 ESLint, TypeScript, 빌드, Docker/PostgreSQL 마이그레이션 CI.
- 개발 API의 실제 누락 수는 공개 상세 응답으로 다시 측정한다. 이 수정만으로 새 사진을 승인·공개했다고 주장하지 않는다.

## 근거와 제한

- 2026-10-28 개발 공개 API 42개 축제 조회: 출연진 351항목 중 `imageUrl` 누락 33개, 시간표 115건 중 2건. 이 수치는 이미지 바이너리 로딩을 검증하지 않는다.
- 현재 구현 `src/modules/public/public-festival.service.ts`의 `missingArtistImages()`는 발행 팩에 `projectPack()`만 적용하지만, 공개 팩은 `publishedWithEtag()`에서 이미지 SQL·현재 출연진·overlay를 적용한다.
- 실제 누락 사진의 인물 확인과 이용 권리 승인, 수집 소스 추가는 후속 작업이며 이슈 #139를 완료 처리하지 않는다.
