# 발견 축제 관리 초안 가져오기

## 목적

공개 축제 목록의 `status: discovered` 축제를 관리자 초안으로 가져온다. 공개 목록의 축제 ID를 그대로 사용하므로 기수 코드 등 관리자 데이터가 같은 축제를 가리킨다. 가져오기는 발행을 수행하지 않으며 기존 공개 발견 상세를 유지한다.

## API

`POST /api/v1/admin/festivals/discovered/{id}/import`

- 인증: 관리자 Bearer JWT, `editor` 이상.
- 경로 `id`: 공개 축제 목록의 `fst_` ID.
- 본문: `{ "days": [{ "date": "2026-11-20", "startsAt": "2026-11-20T12:00:00+09:00", "endsAt": "2026-11-20T22:00:00+09:00" }] }`.
- `days`는 1~7개이고 오름차순이어야 한다. 첫날과 마지막 날은 현재 발견 축제의 `firstDate`·`lastDate`와 같아야 한다. 각 날짜의 시작·종료 시각은 ISO 8601 초 단위와 UTC 오프셋을 포함하고, 시작이 종료보다 빨라야 하며 하루 최대 18시간이다.
- 공개 발견 데이터에는 시작·종료 시각이 없으므로 클라이언트가 공식 자료를 확인해 입력한다. 요청에 이름·장소·출처·ID를 받지 않는다.

## 응답

- `201`: 관리자 초안 문서. `id`는 공개 발견 ID와 같고 `draftVersion: 1`이다. 아직 발행하지 않으므로 DB의 `publishedVersion`은 0이다. 전역 응답 포맷인 `code`, `data`, `message`로 감싼다.
- `400`: 날짜 범위 또는 초안 검증 실패.
- `401`/`403`: 인증 또는 관리자 역할 오류.
- `404`: 해당 ID가 현재 공개 발견 카탈로그에 없음.
- `409`: 같은 ID의 관리자 축제가 이미 있음. 동시 요청 시에도 한 건만 생성한다.

초안에는 서버가 검증한 이름·장소·출처 URL·포스터 또는 보관 이미지·예매 링크를 넣는다. 무대·공연·존·깃발은 비어 있다. 관리자는 `GET /api/v1/admin/festivals/{id}/draft`에서 초안을 확인하고 기존 수정·발행 API를 사용한다. 생성과 감사 기록은 같은 DB 트랜잭션이다.
