# 발견 축제 관리 초안 가져오기

## 목적

공개 축제 목록의 `status: discovered` 축제를 관리자 초안으로 가져온다. 공개 목록의 축제 ID를 그대로 사용하므로 기수 코드 등 관리자 데이터가 같은 축제를 가리킨다. 가져오기는 발행을 수행하지 않으며 기존 공개 발견 상세를 유지한다.

## API

`POST /api/v1/admin/festivals/discovered/{id}/import`

- 인증: 관리자 Bearer JWT, `editor` 이상.
- 경로 `id`: 공개 축제 목록의 `fst_` ID.
- 본문 생략, `{}` 또는 `{ "days": [] }`: 날짜만 확인된 비공개 미완성 초안을 만든다. 서버의 `firstDate`·`lastDate`를 읽기 전용 `eventPeriod`에 보존하고, 운영 시간을 추정하지 않는다.
- 검증된 시각이 있으면 기존 `{ "days": [{ "date": "2026-11-20", "startsAt": "2026-11-20T12:00:00+09:00", "endsAt": "2026-11-20T22:00:00+09:00" }] }` 입력을 유지한다. `days`는 최대 32개이고 오름차순이어야 한다. 비어 있지 않으면 첫날과 마지막 날이 현재 발견 축제의 `firstDate`·`lastDate`와 같아야 한다. 각 날짜의 시작·종료 시각은 ISO 8601 초 단위와 UTC 오프셋을 포함하고, 시작이 종료보다 빨라야 하며 하루 최대 18시간이다. 명시적인 `days: null`은 거부한다.
- 공개 발견 데이터에는 시작·종료 시각이 없으므로 클라이언트는 공식 자료를 확인한 시각만 입력한다. 요청에 이름·장소·출처·ID·`eventPeriod`를 받지 않는다.

## 응답

- `201`: 관리자 초안 문서. `id`는 공개 발견 ID와 같고 `draftVersion: 1`이다. 아직 발행하지 않으므로 DB의 `publishedVersion`은 0이다. 전역 응답 포맷인 `code`, `data`, `message`로 감싼다.
- `400`: 날짜 범위 또는 초안 검증 실패.
- `401`/`403`: 인증 또는 관리자 역할 오류.
- `404`: 해당 ID가 현재 공개 발견 카탈로그에 없음.
- `409`: 같은 ID의 관리자 축제가 이미 있음. 동시 요청 시에도 한 건만 생성한다.

초안에는 서버가 검증한 이름·장소·출처 URL·포스터 또는 보관 이미지·예매 링크와 `eventPeriod`를 넣는다. 무대·공연·존·깃발은 비어 있다. 관리자는 `GET /api/v1/admin/festivals/{id}/draft`에서 초안을 확인하고 기존 수정·발행 API를 사용한다. `days`가 비어 있는 동안 발행과 시작 알림은 거부된다. 발행에는 검증된 시각·무대·공연 세트가 필요하다. 생성과 감사 기록은 같은 DB 트랜잭션이다.
