# Live Activity 원격 시작 전송 계약

## 대상과 예약

공개 버전이 있는 축제의 첫 행사일 `startsAt`에 기기별로 한 건을 예약합니다. `device_subscriptions`에서 해당 축제를 핀하고 `festivalStarts`를 켠 기기 중 `liveActivityPushToStartToken`과 APNs 환경이 등록된 기기만 대상입니다. 이미 `liveActivityId`가 등록된 기기에는 새 Activity를 시작하지 않습니다. 이벤트 키 `live-activity-start:<festivalId>`와 기기 ID의 유니크 제약으로 같은 축제의 여러 행사일이나 스케줄러 인스턴스가 작업을 중복 생성하지 못합니다.

전송 직전에도 공개 상태, 구독, 기기 토큰, 일정 및 현재 Activity를 다시 조회합니다. 시작 페이로드는 공개 팩의 공연 정보를 사용하고, 개인 계정 정보는 포함하지 않습니다. iOS가 시작 후 별도 업데이트 토큰을 등록하면 기존 Live Activity 갱신 경로에서 개인화된 상태를 전송합니다. 일반 APNs 기기 토큰과 개별 Activity 업데이트 토큰은 원격 시작에 사용하지 않습니다.

## 재시도와 결과

APNs 호출 전에 작업을 `failed/OUTCOME_UNKNOWN`으로 내구 기록합니다. APNs 수락 응답은 `sent`로 바꾸고, 명확한 거절 응답은 최대 6회 재시도합니다. 네트워크 타임아웃·응답 불명 또는 전송 중 프로세스 종료는 APNs가 이미 수락했을 가능성이 있으므로 자동 재발송하지 않습니다. 이 정책은 중복 Activity를 막는 대신 결과가 불명확한 단일 전송이 누락될 수 있습니다. 무효 start 토큰은 그 값이 여전히 등록되어 있을 때만 지우며 일반 알림·Activity 업데이트 토큰은 유지합니다.

## 미완료 검증

백엔드 단위 테스트와 CI 통과는 실제 APNs 수신을 증명하지 않습니다. iOS #58의 실기기에서 시작, 새 업데이트 토큰 등록, 갱신 및 종료를 개발 APNs 환경으로 확인한 뒤 #246 완료 여부를 판단합니다.
