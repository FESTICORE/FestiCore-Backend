# 팩 길안내 위도·경도 (#223)

## 목적

Figma 팩 상세의 `가는 길`에서 기기가 외부 지도 앱으로 이동할 목적지를 정확하게 표시한다. 원본에서 확인되지 않은 좌표나 행사장 입구는 추측하지 않는다.

## 계약

- 공개 팩 `directions.location`은 검증된 장소에 한해 `{ latitude, longitude, label, source }`를 내려준다. `latitude`·`longitude`는 숫자이며 각각 `[-90, 90]`, `[-180, 180]` 범위다. `label`은 원본 지도에 표시된 목적지명이다. `source`는 원본 페이지 URL과 확인 시각을 포함한다.
- 좌표가 없거나 원본 장소와 축제 장소가 맞지 않으면 `location: null`이다. 기존 `mapLinks`와 교통 안내는 그대로 사용한다. 클라이언트는 `location`이 있을 때 지도 앱의 좌표 검색을 사용한다.
- 미발행 발견 축제의 공개 상세도 검증된 `location`을 내려준다. 발견 축제의 팩 GET은 발행 전까지 404를 유지한다.
- 관리자 초안 `directions.location`은 선택 사항이다. 유효하지 않은 좌표, 단일 축만 있는 값, 빈 목적지명, 검증 출처 없는 값은 저장·발행하지 않는다. 기존 초안과 팩은 `location: null`로 호환된다.

## 수집과 출처

- 멜론티켓 공연 상세 HTML에서 해당 공연장의 `global_ticket_performanceHall_locLati`/`locLogi`와 `빠른길 찾기` 링크를 함께 확인한다. 두 좌표가 다르거나 지도 목적지명이 공연장과 불일치하면 자동 게시하지 않는다.
- 공연별 원본 URL에서 좌표를 읽어 후보에 저장하고, 관리자 제안 승인 시 `directions.location`에 이관한다. 이미 승인된 축제에 좌표가 새로 확인되면 `directions.diff` 검토 제안을 만든다. 발견 축제 가져오기는 검증된 좌표를 초안에 보존한다. 축제 ID·장소·좌표를 코드에 고정하지 않는다. 재수집에서 좌표가 사라진 경우 기존 검증 좌표를 자동으로 지우지 않는다.
- 기존 멜론 상세 소스는 HTML 해시가 같아도 좌표 파서 도입 후 한 번 재파싱해야 한다. 소스에 파서 버전 마커를 남기고 이후 동일 HTML에서는 새 제안을 반복 생성하지 않는다.
- 공개 발견 상세의 좌표는 승인 이전이라도 **동일 공연의 공식 페이지에서 두 근거가 일치할 때만** 제공한다. 기존 미발행 관리자 초안에 새로 확인된 `directions.diff` 좌표도 공식 근거로 사용할 수 있다. 원본 URL 및 확인 시각을 함께 기록한다.
- 광역 장소나 대표점은 행사장 입구로 표기하지 않는다. 일치 기준이 모호하면 좌표 없이 장소명과 기존 링크만 제공한다.

## 검증

- 공식 멜론 HTML fixture: 정상 좌표, 누락·범위 초과·NaN·서로 다른 좌표·다른 공연장 링크·HTML 이스케이프.
- 후보→승인 초안→공개 팩 및 발견 상세까지 출처와 좌표가 보존되는지 검증한다.
- 공개 projection이 내부 필드와 신뢰하지 않는 좌표를 노출하지 않는지 확인하고, 공개 팩 projection 버전을 올려 ETag/cache를 갱신한다.
