# Railway 환경변수 보안 공지 대응 (#57)

## 현재 확인 범위 (2026-10-22)

Railway는 환경변수 저장 시스템의 비정상 접근과 일부 값의 평문 노출 가능성을 공지했다. 모든 Railway 환경변수와 외부 레지스트리 자격 증명의 교체 및 서비스 로그 점검을 권고한다. FestiCore의 노출 여부는 확인되지 않았다. [Railway 공식 공지](https://blog.railway.com/p/security-disclosure-wednesday-october-21st)

위 집계에는 요청 본문, 토큰, IP, 전체 URL을 저장하지 않았다. 로그가 없다는 사실을 이상 접근이 없었다는 증거로 사용하지 않는다.

## 교체 순서

1. Railway 계정 접근 기록과 공급자별 사용 기록을 확보한다. 비밀값과 원본 로그는 GitHub 이슈·PR·문서에 붙이지 않는다. 필요하면 공급자 콘솔에서 키 ID, 발급·최종 사용 시각만 기록한다.
2. 개발·운영 각각의 백엔드, AdminWeb, Postgres, Redis, 이미지 버킷에 설정된 **변수 이름과 참조 관계**를 확인한다. `railway variables`의 원본 출력은 값을 포함할 수 있으므로 터미널 출력·CI 로그·이슈에 남기지 않는다.
3. 공급자에서 새 자격 증명을 먼저 발급하고 개발 환경에 연결한다. Google OAuth, Apple Sign in, APNs 키는 각각 공급자 콘솔의 유효한 키 ID와 앱 식별자를 확인한다. 이미지 버킷은 개발·운영 버킷을 따로 확인한다.
4. 노출이 확인되거나 악용 정황이 있는 키는 서비스 중단 가능성을 감수하고 즉시 공급자에서 폐기·차단한다. 그 밖의 키도 Railway 권고에 따라 지체 없이 교체하되, 새 키를 발급할 수 있으면 먼저 발급해 전환 시간을 줄인다. 빌드·배포 중단으로 전환할 수 없는 동안에는 공급자 측 사용 제한·권한 축소와 서비스 영향 범위를 기록한다.
5. Railway 빌드·배포가 복구되면 개발 서비스를 배포하고 아래 기능을 확인한다. 그다음 운영에 새 키를 적용하고 동일하게 확인한다. 새 키가 동작하면 기존 키를 공급자에서 폐기하고 최종 사용 시각을 확인한다. 교체 시각, 검증 결과, 미완료 항목만 #57에 기록한다. 비밀값은 기록하지 않는다.

## 검증과 완료 조건

- 개발·운영의 배포가 `SUCCESS`이고 `/api/v1/health`가 정상이다. 대기 중인 배포를 중복 재시작해 대기열을 늘리지 않는다.
- 각 환경에서 Google·Apple 로그인, JWT 갱신, DB 조회, Redis 연결 상태(`GET /api/v1/health` 응답의 `data.redis = up`)와 캐시 읽기·쓰기, 이미지 저장, APNs 테스트 푸시와 실기기 수신을 확인한다. Redis가 down이어도 DB 폴백으로 헬스체크는 HTTP 200일 수 있다.
- DB 접근 기록과 평문 보관 OAuth 갱신 토큰의 노출 가능성을 평가하고, 필요한 공급자 토큰 폐기·재로그인 조치를 완료한다.
- 계정·프로젝트 감사 기록, 서비스 HTTP·네트워크 로그, 공급자 사용 기록의 확인 범위와 한계를 #57에 남긴다.
- 공급자에서 기존 키가 폐기됐고 새 키만 동작하는지 확인한다. 그 전에는 #57을 닫지 않는다.

Railway 장애와 배포 상태는 [공식 상태 페이지](https://status.railway.com/)와 각 환경의 배포 ID로 다시 확인한다.
