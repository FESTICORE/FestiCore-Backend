# 상태·집결 푸시 (API v0.2)

## 목적과 근거

API 명세 v0.2 p8, p36의 `flag.status`, `crew.status`, `crew.gather`를 실제 팔로워·크루원에게 전달한다. 상태 변경과 집결 요청 API는 이미 존재하지만 현재는 APNs 전송 작업을 만들지 않는다. 관리자 테스트 푸시 성공은 실제 사용자 알림의 검증 근거가 아니다.

## 요청과 응답

기존 `POST /api/v1/flags/:id/status`, `POST /api/v1/crews/:id/status`, `POST /api/v1/crews/:id/gather`의 요청·응답은 각각 [flags.md](flags.md), [crews.md](crews.md)를 따른다. 푸시 전송은 비동기 작업이며 API 성공 응답을 APNs 수신 성공으로 해석하지 않는다.

## 알림 계약

- `flag.status`: 공개 깃발의 팔로워에게 보낸다. `resting` 상태는 제외하고 같은 깃발의 연속 변경은 수신자별 5분 창에서 최신 상태로 병합한다.
- `crew.status`: 같은 크루의 다른 멤버에게 보낸다. 수신자별 1분 창에서 최신 상태로 병합한다.
- `crew.gather`: 같은 크루의 다른 멤버에게 집결 위치와 요청자를 보낸다. 상태 알림과 별개이며 기존 10분 집결 쿨다운을 유지한다.
- 대상 계정의 `pushOptIn=false`이면 두 상태 알림을 보내지 않는다. 집결 요청은 이 선택과 무관하게 전달한다.
- APNs 토큰이 없거나 폐기된 기기, 계정·팔로우·크루 관계가 없어졌거나 깃발이 숨김·휴식 상태인 대상은 전송 직전에 제외한다. 현재 사용자 차단 관계 모델은 없으므로 차단 검증은 별도 구현 대상이다. 작업은 원본 상태 변경과 같은 트랜잭션에서 기록해 요청 실패 시 함께 롤백한다.
- 동일 Idempotency-Key 재전송은 상태와 알림 작업을 중복 생성하지 않는다. 작업 처리 실패는 제한된 재시도 후 기록하고, API 쓰기 자체는 되돌리지 않는다.

## 검증 기준

상태·집결별 수신자 선택, `pushOptIn` 분기, `resting` 제외, 5분·1분 병합, 멱등 재전송, 트랜잭션 롤백, 기기 토큰 삭제 후 취소, APNs 실패 재시도를 확인한다. 현재 자동 검증은 모의 SQL/APNs 단위 테스트와 빌드까지이며 PostgreSQL 마이그레이션·실기기 APNs 수신은 별도 확인이 필요하다.
