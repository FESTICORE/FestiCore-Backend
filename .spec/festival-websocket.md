# 공개 축제 팩 실시간 갱신

- 연결: `wss://<API 호스트>/api/v1/festivals/updates` (로컬은 `ws://`). 공개 읽기 전용이며 로그인 토큰과 기기 비밀값을 요구하지 않는다.
- 서버 메시지: `{ "event": "pack.updated", "data": { "festivalId": "fst_...", "packVersion": 2 } }`. 본문이나 비공개 깃발 데이터는 전송하지 않는다.
- 클라이언트는 버전이 로컬보다 높을 때 `GET /api/v1/festivals/{id}/pack`을 다시 요청하고 성공한 팩을 기기에 저장한다. 재연결 때도 목록 ETag와 저장된 팩 버전을 비교한다. 오프라인 중 실시간 전달은 불가능하다.
- 관리자의 발행·롤백 및 깃발 프로필로 인한 공개 팩 변경은 모두 알림 대상이다. DB 트랜잭션이 확정된 버전만 알린다. WebSocket 연결 자체는 수신 확인이나 영구 전달을 보장하지 않는다.
- 연결 시 Origin은 허용된 웹 Origin만 받고, Origin이 없는 네이티브 앱은 허용한다. 허용되지 않은 Origin은 HTTP 업그레이드 전에 403으로 거절한다. IP별 연결 수와 메시지 크기를 제한하며 서버는 클라이언트 명령을 받지 않는다.

## 구현과 검증

- NestJS `ws` 어댑터를 같은 HTTP 서버에 연결한다. 부팅 시 기존 축제 버전을 기준값으로 읽어 재배포 직후의 대량 알림을 피한다. 이후 여러 인스턴스가 공유하는 Postgres의 **커밋된** 축제 ID·공개 버전만 3초마다 읽고 축제별 최종 버전으로 중복을 제거한다. 팩 JSON은 읽지 않는다. 연결이 없으면 DB 조회를 건너뛴다. 부팅 직전 변경이나 연결 공백 중 변경의 복구는 기존 REST 재동기화가 담당한다.
- 연결 상한은 기본 인스턴스당 5,000개·IP당 500개이며 `WS_MAX_CLIENTS`, `WS_MAX_CLIENTS_PER_IP`로 조정한다. 연결이 끊긴 단말은 30초 ping/pong 검사로 정리한다. 행사장 공용 IP 수용량은 운영 환경에서 조정한다.
- `npm test -- --runInBand`에서 연결 경로, 허용·거부 Origin, 읽기 전용 동작, 버전 중복 제거를 검증한다. `npm run build`와 변경 파일 ESLint를 통과해야 한다.
- Railway 개발·운영 인스턴스의 실제 `wss://` 프록시 연결과 모바일 재연결 동작은 배포 후 별도로 확인한다.
