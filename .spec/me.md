# 내 계정 API

모든 경로는 `/api/v1` 기준이며 앱 access 토큰을 `Authorization: Bearer <token>`으로 보낸다.
관리자 세션이나 refresh 토큰은 사용할 수 없다.

| 메서드 | 경로 | 요청 본문 | 성공 |
| --- | --- | --- | --- |
| GET | `/me` | 없음 | 200, 현재 사용자 정보 |
| PATCH | `/me` | `{ "nickname": "축제관객" }` (1~12자) | 200, 변경된 사용자 정보 |
| DELETE | `/me` | `{ "confirm": "DELETE" }` | 204, 본문 없음 |

`GET /me`는 내 정보 확인, `PATCH /me`는 닉네임 변경, `DELETE /me`는 계정 탈퇴에 사용한다.
깃발 핀 변경은 별도 경로 `PUT /me/pinned-flag`에서 처리한다.
필수 본문이 없거나 형식이 틀리면 400, 유효한 앱 access 토큰이 없으면 401이다.

현재 `/auth/me`의 GET·DELETE는 과거 호환 경로다. DELETE는 확인 문자열 없이
200을 반환하므로 `/me`와 계약이 다르다. 클라이언트는 `/me`를 사용해야 한다.
서버가 호환 경로를 폐기할 시점은 별도 마이그레이션으로 결정한다.

## 명세와 남은 차이

API 명세 v0.1의 `PATCH /me` 본문은 `nickname?`으로 표시되어 있으나 현재
닉네임만 변경할 수 있어 값을 필수로 검증한다. 또한 계정 삭제 시 기수·크루 소유권
이전과 Apple revoke 실패 재시도 큐까지 명세가 요구한다. 현재 서비스에는 이 후처리가
완료되지 않았으므로 탈퇴 흐름 구현과 테스트를 별도로 보강해야 한다.
