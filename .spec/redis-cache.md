# 스펙: 공개 팩 Redis 캐시

## 범위

`PublicFestivalService.published(id)`의 공개 팩 문서만 캐시한다. `REDIS_URL`이
없으면 캐시를 비활성화하고 Redis 연결을 시도하지 않는다. Redis 명령이나 연결이
실패해도 DB 조회와 기존 응답이 계속 동작한다.

## 키와 조회

1. `pack:<festivalId>:gen`을 읽는다. 키가 없으면 무작위 양의 정수를 `SET ... NX`로
   시드한 뒤 다시 읽는다. 세대 키가 삭제되거나 Redis가 재시작돼도 과거 `g0` 팩을
   다시 읽지 않기 위한 절차다. 시드 또는 재조회가 실패하면 DB로 폴백한다.
2. `pack:<festivalId>:g<generation>`의 JSON 문서를 읽는다.
3. 캐시가 없으면 DB에서 공개 팩을 조회하고 `projectPack` 결과를 **처음 읽은 세대**의
   키에 TTL 3600초로 저장한다. 미공개 팩의 404 응답은 저장하지 않는다.

Redis 명령은 최대 500ms에 타임아웃되며 오프라인 큐를 사용하지 않는다.
명령 실패는 캐시 미스로 처리한다. 연결 장애와 복구는 상태 전환 시 한 번씩만 기록한다.

## 무효화

발행, 롤백 또는 깃발·사진·숨김 변경으로 공개 팩이 바뀌면 DB 트랜잭션 커밋 후
`INCR pack:<festivalId>:gen`을 실행한다. 조회가 이전 세대를 읽고 그 키에 늦게
저장하더라도 이후 조회는 새 세대 키를 사용한다. 무효화 실패도 응답에는 영향을 주지
않으며 캐시 문서의 3600초 TTL이 최종 안전망이다.

## 운영 상태

`GET /api/v1/health`의 `data.redis`는 연결 상태에 따라 `up`, `down`,
`disabled`를 반환한다. Redis는 선택 의존이므로 상태가 `down`이어도 DB가
정상이라면 HTTP 200이다. DB `SELECT 1` 실패의 기존 503 계약은 유지한다.

Redis 연결은 `family: 0`으로 IPv4·IPv6 주소를 모두 허용한다. Railway 사설망이
IPv6 주소만 제공해도 접속할 수 있도록 한다.

목록 조회, 라이브 보드, 레이트리밋, CDN은 이 캐시의 범위에 포함하지 않는다.
