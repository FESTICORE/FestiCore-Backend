# Admin analytics

`GET /api/v1/admin/analytics/sentry?from=YYYY-MM-DD&to=YYYY-MM-DD&project=ios|backend`
and `GET /api/v1/admin/analytics/mixpanel?from=YYYY-MM-DD&to=YYYY-MM-DD`
require an administrator with `viewer` or higher role. Dates are inclusive KST calendar dates, limited to 31 days and today or earlier. Responses use the global `{code,data,message}` envelope.

## Configuration

- `ANALYTICS_ENVIRONMENT`: `stage` or `production`; required for Sentry queries.
- `SENTRY_IOS_PROJECT_ID`, `SENTRY_BACKEND_PROJECT_ID`: numeric Sentry project IDs.
- `SENTRY_ANALYTICS_READ_TOKEN`: Sentry read token with `org:read` and `event:read` scopes. Keep separate from SDK DSNs and upload tokens.
- `MIXPANEL_SERVICE_ACCOUNT_USERNAME`, `MIXPANEL_SERVICE_ACCOUNT_SECRET`: service account for project `4078612` in US data residency with raw event export permission (`download_events_csv`). A Consumer account cannot export events; the project role must allow this operation. The public ingestion token cannot replace service account credentials.

Mixpanel upstream 401/403 responses retain `status: error` and add the optional `reason: unauthorized` or `reason: forbidden`. These are analytics source failures, not administrator session failures. An HTTP 200 export containing the exact `terminated early` line returns `status: error` with `reason: incomplete_export`, even after valid event rows. Counts remain null and no upstream response body or credentials are returned. The console can explain the required account configuration without signing the administrator out.

Missing or invalid configuration produces `unconfigured` with `totalEvents: null`; upstream errors produce `error` or `rate_limited`. Sentry's exact `Unknown environments selected` 404 is treated as a real zero only when both Sentry lookups agree or the other lookup returns an empty issue list. Other 404s and auth errors remain errors. Partial Sentry data produces `partial`. Sentry `series` and `totalEvents` count error events in the selected project/environment; issue titles are generic to avoid exposing exception text. Mixpanel export is capped at 10,000 rows and 2 MB. If it reaches the row cap, `status: partial` and `truncated: true`; returned counts are observed lower bounds. If the size cap is exceeded, the response is `error` with no counts. No event properties or raw issue text are returned. Mixpanel also returns `uniqueUsers` (distinct `distinct_id` count in the range), `userSeries` (daily distinct users) and, for each of the top 10 events, `users` and a daily `series`; identifiers themselves are never returned and events without `distinct_id` only count toward event totals. Sentry issues add `userCount`, `level` (`fatal`/`error`/`warning`/`info`/`debug`) and `firstSeen`; values outside those shapes become `null`. Results are cached in memory for 60 seconds on success and 10 seconds otherwise; concurrent identical queries share one upstream request.

`GET /api/v1/admin/analytics/mixpanel/funnel?from=YYYY-MM-DD&to=YYYY-MM-DD&steps=a,b,c` returns an ordered funnel over the same export. `steps` takes 2 to 5 event names that satisfy the public event name rule (lowercase identifier, no 4-digit run); otherwise 400. For each `distinct_id`, events are walked in time order and the user advances one step when the next expected event occurs, so `steps[i].users` is the number of distinct users who reached step `i` after all earlier steps within the range. Mixpanel `time` has second precision, so events in the same second are ordered by their position in `steps`. Events without `distinct_id` are ignored. Failures and `unconfigured` keep the step names with `users: null`; status, `reason` and `truncated` follow the Mixpanel rules above. The parsed export is shared between the Mixpanel summary and funnels for the same range for 60 seconds (failed exports are not shared), so choosing funnel steps does not add upstream export calls.

The Sentry [timeseries](https://docs.sentry.io/api/explore/query-explore-events-in-timeseries-format/) and [issues](https://docs.sentry.io/api/events/list-an-organizations-issues/) APIs and Mixpanel [raw export](https://docs.mixpanel.com/reference/raw-event-export) API define the upstream formats. Credential backed live results require separate validation after configuration.
